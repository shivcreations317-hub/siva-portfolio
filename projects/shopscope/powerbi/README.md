# ShopScope — Power BI build kit

This folder contains everything needed to recreate the ShopScope report in Power BI Desktop. The live web dashboard is a dependency-free prototype of the same analysis; this kit is the Power BI version.

## Files

| File | Purpose |
|---|---|
| `measures.dax` | Copy-paste DAX measures for sales, customers, RFM, returns and cohorts |
| `theme.json` | Importable Power BI theme matching the ShopScope dark palette |
| `powerquery.m` | Power Query M template for loading and typing `orders.csv` |
| `README.md` | Model, relationships, report pages and build steps |

## 1. Load the data

Import these CSVs from `../data/`:

- `orders.csv` — fact table (1,588 rows)
- `customers_scored.csv` — customer dimension with RFM scores and segments (1,000 rows)
- `products.csv` — product dimension (24 rows)
- `returns.csv` — return fact (231 rows)

Use **Get Data → Text/CSV**, then **Transform Data**. The `powerquery.m` template shows the expected types and the derived `Month`, `Quarter` and `Returned` columns. Change the file path in the `Source` step to your local path. `customers_scored.csv` is generated by `python/analyze.py`; run that script after regenerating the raw data.

Create a separate `Date` table for time intelligence:

```dax
Date =
ADDCOLUMNS (
    CALENDAR ( DATE ( 2025, 1, 1 ), DATE ( 2025, 12, 31 ) ),
    "Year", YEAR ( [Date] ),
    "Month Number", MONTH ( [Date] ),
    "Month", FORMAT ( [Date], "MMM" ),
    "Quarter", "Q" & QUARTER ( [Date] )
)
```

Mark it as a date table and sort `Month` by `Month Number`.

## 2. Model

Star schema:

```
Customers 1 ─── * Orders * ─── 1 Products
                     │
                     │ 1
                     *
                  Returns

Date 1 ─── * Orders
```

Relationships:

| From | To | Cardinality | Direction |
|---|---|---|---|
| `Customers[customer_id]` | `Orders[customer_id]` | 1:* | Single |
| `Products[product_id]` | `Orders[product_id]` | 1:* | Single |
| `Orders[order_id]` | `Returns[order_id]` | 1:* | Single |
| `Date[Date]` | `Orders[order_date]` | 1:* | Single |

Hide the raw key columns from the report view. Format `revenue`, `net_revenue`, `profit`, `refund_amount` as currency (₹, 0 decimals), `discount_pct` and rates as percentages.

## 3. Measures

Open `measures.dax` and add the measures to the `Orders` table. The key measures are:

- `Net Revenue`
- `Gross Margin %`
- `Orders`
- `Avg Order Value`
- `Repeat Customer Rate`
- `Return Rate`
- `At Risk Revenue Share`
- `Cohort Retention %`
- `Net Revenue MoM %`

## 4. Report pages

### Page 1 — Executive overview

- KPI cards: Net Revenue, Gross Profit, Orders, AOV, Repeat Customer Rate, Return Rate
- Line and clustered column chart: `Month` on X, `Net Revenue` as columns, `Return Rate` as line
- Donut: `Products[category]` by `Net Revenue`
- Bar: Top 6 products by `Net Revenue`
- Slicers: Date, Category, Channel, Segment

### Page 2 — Customer retention

- RFM segment table: segment, customers, net revenue, revenue share, AOV, repeat rate
- Cohort matrix: `Customers[cohort_month]` rows, `Orders[cohort_index]` columns, `Cohort Retention %` values
- Card: Repeat Revenue Share
- Card: At Risk Customers and At Risk Revenue Share
- Scatter or bar: acquisition channel vs repeat rate

### Page 3 — Returns and product quality

- KPI cards: Return Rate, Returned Orders, Refund Value
- Bar: return reasons
- Bar: return rate by category
- Table: product, category, orders, return rate, refund value
- Slicers: Category, Channel, Segment

## 6. Notes

- The dataset is synthetic and deterministic (`python/generate_data.py`).
- The web dashboard reads the same enriched extract from `data/dashboard-data.js`.
- If you regenerate the data, rerun `python/analyze.py` before refreshing Power BI so the RFM and cohort fields stay in sync.
- The `Cohort Retention %` measure needs a visual-level filter to hide future periods for recent cohorts. The comment in `measures.dax` explains the logic.
